Release verification results

Comparison method

Reference WRF builds

The references use the GNU build of WRF v4.8.0 on x86-64 Intel, with gfortran 14.2 and Debian 13 glibc 2.41, run in one process. FP64 uses -fdefault-real-8, with -fdefault-double-8 where the reference requires it. FP32 uses stock WRF real*4.

Variables and output times

Runs start from the same inputs. For each exact check, CPPWRF compares every reference variable and output time at tolerance 0, including types and attributes. Signed zeros differ, and NaNs compare equal to one another. Separate checks cover WRF-format restart files and resumed runs.

Column and kernel tests

CPPWRF and WRF’s compiled Fortran routines receive the same inputs. The tests compare CPU FP64 outputs at tolerance 0.

Precision and backend

CPU and CUDA FP64 target WRF real*8. CPU FP32 and default CUDA FP32 target WRF real*4 on the verified configurations. The opt-in fast CUDA FP32 build compares fields by relative L2 error.

Verified coverage

Dynamics, physics and I/O

The verified options include split-explicit RK3 dynamics, diffusion and advection, microphysics, cumulus, boundary-layer and surface schemes, and radiation. The suite also covers grid nudging, static one-way and two-way nests, WRF-format history and restarts, and WRF idealized cases.

Cases and layouts

The suite exercises real-data and idealized cases, including a three-domain two-way nest in CPU and CUDA FP64. FP32 identity covers 24 configurations. Tiled and MPI checks apply to the configurations run in those layouts.

Known limits

  • Bit identity applies to verified configurations and the specified WRF reference toolchain. FP32 identity coverage excludes restarts, vertical refinement and runs with more than two domains.
  • Moving nests, ndown.exe, multilayer urban models and the lake model are unported. CPPWRF rejects unported namelist options. Some ported schemes and options are restricted to a single domain.
  • Native restart files have limits with nests, adaptive time stepping and tmn_update. For those configurations, use WRF-format wrfrst files.
  • MPI runs give WRF’s bits in every tested layout on one machine: up to 48 CPU ranks, and CUDA FP64 on two T4 GPUs in nine layouts. Runs across several nodes use the same code and have not been tested yet.
  • The paper documents verification with GCC on x86-64 Linux. The opt-in HIP build path still needs runtime verification on AMD GPUs.
  • The 72-hour WRF comparison for the two-way nest N3 remains open.
